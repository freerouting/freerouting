## Method

1. Enumerated current-tree `ObjectInputStream`, custom `readObject`, and Java serialization call
   sites; frozen `src_v19/` results were excluded.
2. Traced the `.frb` GUI file-open flow from `RoutingJob.setInput(File)` and format detection through
   `BoardFrameFileActions.open`, `BoardFrame.load`, `GuiBoardPersistence.loadFromBinary`, and the
   subsequent viewport/subwindow reads.
3. Traced REST/MCP job input into `BoardLoader` and `RoutingJobScheduler`; both accept only DSN and
   KiCad JSON for routing and reject FRB before any `ObjectInputStream` call.
4. Traced board snapshot, undo, history, strict-DRC, and deep-copy callers to verify that their
   byte arrays are created by the process and consumed internally.
5. Searched for `ObjectInputFilter`, `setObjectInputFilter`, global serial-filter configuration, and
   other application deserialization guards. No application-defined filter was found. No production
   code was changed and no risk-register rows were added.

## Controls verified during the hunt

- `BoardLoader.loadBoardIfNeeded` explicitly rejects every input format except DSN and
  `KICAD_DESIGN_JSON` (`management/BoardLoader.java:31-37`).
- `RoutingJobScheduler` branches only on DSN/JSON and marks other formats invalid
  (`management/jobs/RoutingJobScheduler.java:83-95,183-186`).
- REST `JobInputResource` accepts Base64/raw JSON through Gson and `BoardFileDetails`; it does not
  construct an `ObjectInputStream`.
- `BoardSnapshotManager.deserialize`, `BasicBoard.deserialize`, `BoardHistory.restoreBoard`, and
  `RoutingBoardUndoFacade.deepCopy` consume snapshots generated by the same process; no API,
  MCP, or persisted untrusted byte source was found.
- `.frb` loading is reached from the GUI file-menu open action. The drag-and-drop path intentionally
  accepts only DSN and KiCad JSON (`BoardFrame.java:1153-1162`).
- The `.frb` stream contains application board/workspace state followed by AWT and subwindow state;
  all reads occur on the same unfiltered stream (`BoardFrame.java:807-843`).

## Candidates not promoted

- Internal `readObject` implementations in `BasicBoard`, `Communication`, `BoardRules`,
  `GraphicsContext`, and `WorkspaceSettings` reset transient state or restore application fields;
  no direct file/network/process side effect was found beyond object construction.
- `ObjectOutputStream` writers and `UndoableObjects.readObject` are not external deserialization
  boundaries.

### Confirmed — GUI `.frb` load is unrestricted Java deserialization (High, local)

`BoardFrameFileActions.open` reads the chosen file into a `byte[]` and, when the format is
`FRB`, calls `BoardFrame.load(..., FileFormat.FRB, ...)`. Any format that is not DSN or
KiCad JSON takes the `else` branch:

```807:814:src/main/java/app/freerouting/gui/board/BoardFrame.java
      ObjectInputStream objectStream;
      try {
        objectStream = new ObjectInputStream(inputStream);
      } catch (IOException _) {
        this.updateTexts();
        return false;
      }
      boolean readOk = boardPanel.boardHandling.loadFromBinary(objectStream);
```

`GuiBoardPersistence.loadFromBinary` then `readObject()`s a `RoutingBoard`,
`WorkspaceSettings`, coordinate transform, and `GraphicsContext`. Casts run **after**
construction. The same stream then reads AWT `Point`/`Rectangle` and subwindow state.
There is no `ObjectInputFilter` and no class allowlist.

Reachability that was **not** found:

- `BoardLoader` and `RoutingJobScheduler` accept only DSN and KiCad JSON.
- REST/MCP uploads never construct `ObjectInputStream`.
- CLI `loadBoardFromFile` is DSN/JSON only.
- Drag-and-drop rejects FRB (`BoardFrame.java:1159-1162`).

Threat-model T-G1 therefore stays a **P1 local-file** issue. Keep **High** for a
user-opened hostile `.frb` (unrestricted native deserialization). Do **not** promote to
Critical: no network-reachable path was confirmed, and no gadget chain was demonstrated
on this classpath. Without a gadget, residual impact is still GUI process DoS.

### Confirmed — internal snapshots use the same unfiltered deserializer (Medium)

`BoardSnapshotManager.deserialize` wraps caller bytes in `ObjectInputStream` with no
filter. Callers (`BasicBoard.clone`/`deserialize`, `BoardHistory.restoreBoard`,
`RoutingBoardUndoFacade.deepCopy`, strict-DRC restore) pass arrays that the same process
just wrote. That is T-G2: not an external RCE boundary.

The Medium claim that remains is availability: a huge or pathological in-memory board
(from untrusted DSN/JSON, Pass C/H) can be serialized and deserialized again, adding
CPU/heap cost. Keep **Medium**. Do not treat this as a second High/Critical RCE row.

Do not add Pass G findings to the risk register until Phase 3. Next hunter: **GPT-5.6
Luna Max** for Pass H, or **GPT-5.6 Luna High** for Passes E and F.
